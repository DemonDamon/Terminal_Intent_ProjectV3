## 一、版本背景与核心问题

### 1.1 v0.5.1 现状

v0.5.1 完成了 E8-E12 优化（阈值搜索扩展、特征压缩、样本降权），验证集（9月）指标已达预期。

**未解决的关键问题**：模型在 10 月测试集上泛化崩溃（AUC 0.99 → 0.68），根因分析指向三个方向：

| # | 问题 | 影响 | 优先级 |
|---|------|------|:------:|
| 1 | E8 扩展后 [0.10, 0.30) 区间正负样本重叠程度未知 | 阈值选择缺乏数据支撑 | **P0** |
| 2 | 核心特征无单调性约束，小样本区间可能学出反直觉分裂 | 跨月决策翻转 | **P1** |
| 3 | E9 的 sqrt 压缩改变了 E10 交叉特征语义 | 犹豫用户信号衰减 24%~41% | **P2** |
| 4 | 验证集同时用于调参和评估，9 月指标偏乐观 | 无法无偏评估真实效果 | **P2** |
| 5 | 10 月数据抽取使用随机采样，未对齐回测用户名单 | 回测结论不可信 | **P1** |
| 6 | 部分特征在 8-9 月 vs 10 月分布漂移严重 | 泛化崩溃的根因之一 | **P1** |

### 1.2 v0.5.2 目标

本版聚焦泛化能力修复与诊断工具建设：

1. **诊断先行**：概率分布分析（P0）+ PSI 特征稳定性诊断
2. **模型加固**：单调性约束（P1b）+ 交叉特征修复（P2a）
3. **验证增强**：三层时间切分（P2b）+ 10 月无偏测试
4. **数据修正**：回测用户名单筛选替代随机采样

## 三、P0：概率分布分析

### 3.1 问题

E8 将阈值搜索下界从 0.30 扩展到 0.10，隐含假设是 [0.10, 0.30) 区间内存在大量可回收的正样本。但该假设在 v0.5.1 中未经数据验证，如果该区间正负样本比接近 1:1，扩展阈值反而会让 Precision 崩塌。

### 3.2 方案

在 `train_pipline.py` 中新增 `analyze_probability_distribution()` 函数，训练后自动输出概率分布诊断报告。同时将原先内联的验证集评估代码抽取为 `print_evaluation_report()` 复用函数。

## 四、P1b：单调性约束

### 4.1 问题

`click_to_process_rate`、`view_detail_cnt` 等特征与购机意向应为单调递增关系。但 LightGBM 可能在小样本区间学出非单调分裂（如"浏览 20 次以上反而降低预测概率"），这种反直觉分裂在训练集上降低损失，但在新数据上失效——这是 10 月泛化崩溃的原因之一。

### 4.2 方案

在 `auto_train` 中新增 `monotone_features` 参数，对指定特征施加单调递增约束。

### 4.3 具体改动

**修改文件 1：`src/models/model_lgb.py`**

1）`auto_train` 签名新增 `monotone_features` 参数：

```python
def auto_train(self, X_train, y_train, cat_features=None,
               n_trials=15, sample_weight=None, monotone_features=None):
```

2）构建约束列表并注入 Optuna trial + 最终训练参数：

```python
# 【P1】构建单调性约束列表
monotone_constraints = None
if monotone_features:
    feature_list = X_train.columns.tolist()
    monotone_constraints = [1 if f in monotone_features else 0 for f in feature_list]
    # 1=单调递增, 0=无约束
```

在 Optuna `objective()` 和最终 `lgb.train()` 中均添加：

```python

    params['monotone_constraints'] = monotone_constraints
```

**修改文件 2：`train_pipline.py`**

定义约束特征并传参：

```python

                     'high_intent_ratio', 'cnt_bussProcessing']

model_runner.auto_train(X_train, y_train, cat_features=actual_cat, n_trials=30,
                        sample_weight=sample_weight, monotone_features=MONOTONE_FEATURES)
```

### 4.4 约束特征选择依据

| 特征 | 约束方向 | 业务含义 | v0.5 重要性 |
|------|:-------:|---------|:-----------:|
| click_to_process_rate | 单调递增 | 办理转化率越高→意向越高 | #1 (26.05%) |
| view_detail_cnt | 单调递增 | 详情浏览越多→意向越高 | #2 (22.24%) |
| cnt_bussProcessing | 单调递增 | 办理次数越多→意向越高 | #4 (4.52%) |
| high_intent_ratio | 单调递增 | 高意图行为占比越高→意向越高 | #6 (3.14%) |

**未约束的特征**：`avg_action_interval`（间隔长可能代表犹豫也可能代表放弃，非单调）、`price_level`（高价不一定意味高意向）、所有类别特征（LightGBM 不支持类别特征单调约束）。

### 4.5 预期效果

- 消除小样本区间的反直觉分裂，提升跨月泛化能力
- AUC 可能微降 0.001~0.003（约束限制了模型自由度），但 F1 稳定性提升
- 漂移场景下衰减更平缓——单调模型不会因少量噪声翻转决策方向

## 五、P2a：E9/E10 交互缺陷修复

### 5.1 问题

v0.5.1 中 E9 在 E10 之前对 `click_to_process_rate` 做了 sqrt 压缩，再单独赋值。E10 的 `browse_depth_no_click` 交叉特征使用了压缩后的值，导致犹豫用户（rate=0.10~0.25）信号被削弱：

| 原始 rate | sqrt(rate) | 1 - sqrt(rate) | 原始 1-rate | 信号损失 |
|:---------:|:----------:|:--------------:|:-----------:|:--------:|
| 0.10 | 0.316 | **0.684** | 0.90 | **-24%** |
| 0.25 | 0.500 | **0.500** | 0.75 | **-33%** |

### 5.2 方案

修改文件：`src/features/unified_fe.py`

1）将 E9 的两步计算（先原始值再 sqrt）合并为单行：

```python
# 修改前 (v0.5.1)
fe['click_to_process_rate'] = fe['cnt_bussProcessing'] / (fe['cnt_eventClick'] + 1)
fe['click_to_process_rate'] = np.sqrt(fe['click_to_process_rate'])

# 修改后 (v0.5.2)
fe['click_to_process_rate'] = np.sqrt(fe['cnt_bussProcessing'] / (fe['cnt_eventClick'] + 1))
```

2）删除 `browse_depth_no_click` 交叉特征：

```python
# 删除（语义已被 sqrt 破坏，且信号与 view_detail_cnt 高度重叠）
fe['browse_depth_no_click'] = np.expm1(fe['view_detail_cnt']) * (1 - fe['click_to_process_rate'])
```

3）交叉特征重新编号：原 #2 `revisit_intensity` 变为 #1。

### 5.3 影响

- 特征总数减少 1 个（40 → 39），降低过拟合风险
- `click_to_process_rate` 计算逻辑不变，模型训练中使用的仍是 sqrt 后的值
- 删除该特征后若 Recall 下降，可在后续版本用原始 rate 重建

### 8.3 PSI 计算逻辑

**连续特征：**

```python
def calculate_psi(reference, test, bins=10):
    # 1. 按参考集(8-9月)的十分位数切10个桶
    boundaries = np.percentile(ref, np.linspace(0, 100, bins + 1))
    # 2. 统计参考集和测试集在每个桶中的占比
    ref_pct = np.histogram(ref, bins=boundaries)[0] / len(ref)
    tst_pct = np.histogram(tst, bins=boundaries)[0] / len(tst)
    # 3. 占比为0时用 0.0001 替代防止 ln(0)
    # 4. PSI = Σ (test% - ref%) × ln(test% / ref%)
    return np.sum((tst_pct - ref_pct) * np.log(tst_pct / ref_pct))
```

本版所有新增功能均复用已有模块，不引入新依赖：

| 模块 | 来源 | 复用场景 |
|------|------|---------|
| `DataLoader.load_and_clean()` | `src/data/loader.py` | train_pipline.py 加载 10 月数据 / feature_stability.py 加载数据 |
| `UnifiedFeatureEngineer.execute()` | `src/features/unified_fe.py` | feature_stability.py 生成特征 |
| `CAT_FEATURES` | `config/feature_list.py` | feature_stability.py 区分连续/类别特征 |
| `RULE_LAYER_FEATURES` | `config/feature_list.py` | feature_stability.py 包含在分析范围 |
| `IntentModel.auto_train()` | `src/models/model_lgb.py` | 扩展接口支持 monotone_features |

## 十、实施优先级与依赖关系

```
P0（概率分布分析）──── 诊断工具，无外部依赖
  │
  ├─→ P1b（单调性约束）── 独立改动，与 P0 并行
  │
  ├─→ P2a（E9/E10 修复）── 独立改动
  │
  ├─→ P2b（三层切分 + 10月测试）── 依赖10月数据文件
  │
  ├─→ 数据抽取重构 ── 依赖回测用户名单文件
  │
  └─→ PSI 诊断工具 ── 独立脚本，依赖10月数据文件
```

### 推荐验证顺序

| 步骤 | 操作 | 验证点 |
|:----:|------|--------|
| 1 | 运行 `data_extra_withdata.py` 重新抽取 10 月数据 | 确认 `predict_data_10.csv` 包含名单用户的全部事件 |
| 2 | 运行 `feature_stability.py` | 检查 PSI 报告，确认不稳定特征列表 |
| 3 | 运行 `train_pipline.py` | 检查三层切分样本数 / P0 概率分布 / 10 月无偏评估结果 |
| 4 | 对比 v0.5.1 和 v0.5.2 的 10 月 AUC/F1 | 量化泛化改善幅度 |

## 十一、预期目标与成功标准

| 指标 | v0.5.1 (9月验证) | v0.5.1 (10月测试) | v0.5.2 目标 (10月) |
|------|:----------------:|:-----------------:|:------------------:|
| ROC-AUC | 0.990+ | 0.68 (崩溃) | **≥ 0.80** |
| F1 | 0.79~0.82 | — | **≥ 0.50** |
| Precision | 80~85% | — | **≥ 40%** |
| Recall | 73~78% | — | **≥ 60%** |

> **注**：10 月目标显著低于 9 月，是因为跨月分布漂移不可避免。v0.5.2 的核心目标是将崩溃恢复到可用水平，而非追求 9 月同等指标。
