## 二、根因诊断

### 根因 #1（P-Critical）：正样本率分布偏移 6 倍

这是 **Precision 从 85% 崩溃到 48% 的第一驱动因素**。

| | 验证集(9月) | 测试集(10月) | 倍差 |
|---|:---:|:---:|:---:|
| 正样本 | 2,361 | 4,546 | — |
| 负样本 | 32,517 | 407,765 | — |
| **正样本率** | **6.77%** | **1.10%** | **6.15x** |

**原因追溯至 `data_extra_withdata.py`**：

- **8-9 月数据**（训练+验证）：50% 一致性哈希采样 → 采样后正样本率 ~7%（用户被人为富集）
- **10 月数据**（测试）：回测用户名单全量匹配 → 反映真实世界 ~1% 正样本率

结果是：验证集上阈值 0.10 看到的环境是"每 15 人中 1 人购机"，而测试集的环境是"每 91 人中 1 人购机"。相同阈值在负样本密度翻 6 倍的环境下，假阳性成比例增加。

**数学验证**：在排序能力不变的前提下，Precision 与正样本率近似正比。85.31% × (1.10/6.77) ≈ 13.9%。实际结果 48.28% 远好于此下界，再次确认模型排序力极强。

### 根因 #2（P0）：最终模型训练缺少 Early Stopping

`src/models/model_lgb.py` 第 225-229 行：

```python
self.model = lgb.train(
    best_params,
    train_data,
    num_boost_round=1000   # ← 无 early stopping，无 valid_sets
)
```

- Optuna 内部 3-fold CV 使用了 `early_stopping(30)`，实际最优轮次通常在 200-400 轮
- 但最终全量拟合时**跑满 1000 轮**，多出 600+ 棵树全在拟合训练集噪声
- 这是直接且可消除的过拟合源

### 根因 #3（P1）：repeat_view_ratio 特征垄断

单特征贡献 43.92%，意味着模型本质上是一个"重复浏览率分类器"。风险：

1. **脆弱性**：如果该特征在 8 月 vs 10 月之间分布漂移，直接拖垮整个模型
2. **信息浪费**：其他 39 个特征的信号被压制，模型没有学到多元决策边界
3. 虽然已做 `log1p` 压缩（E9），但从 43.92% 的结果看效果不足

### 根因 #4（P2）：E8 区间 [0.10, 0.30) 在测试集上失效

| | 验证集 | 测试集 |
|---|:---:|:---:|
| 正样本 | 167 (7.1%) | 647 (14.2%) |
| 负样本 | 127 | 1,944 |
| **区间精度** | **56.8%** | **25.0%** |

验证集上 >50% 看似有效，测试集上仅 25%。低概率区间的信号在跨月后严重衰减。在排名制下此区间自然被排除在 Top-K% 之外，不再构成问题。

### 根因 #5（P3）：正样本概率分布跨月漂移

| | 验证集 | 测试集 |
|---|:---:|:---:|
| 正样本均值 | 0.7112 | 0.5450 |
| 正样本中位数 | 0.8871 | 0.5961 |
| [0.70, 1.0) 正样本占比 | 66.5% | 43.4% |

正样本在测试集上整体得分偏低（中位数从 0.89 降到 0.60），说明 10 月正样本的行为模式与 8 月训练数据存在漂移。排名制仅依赖相对排序，不受绝对概率值漂移影响。

## 三、核心方案：Top-K% 排名制替代阈值制

### 3.1 为什么阈值制在本场景下失效

阈值制的隐含前提是：**模型输出的概率值在不同环境下具有一致的语义**。即概率 0.5 在 9 月和 10 月都代表"50% 可能性购机"。

但实际情况是：
1. 训练/验证集的正样本率 (~7%) 与真实环境 (~1%) 相差 6 倍
2. LightGBM 的输出概率受 `scale_pos_weight` 和正样本率影响，并非真实概率
3. 特征分布跨月漂移，导致同一用户在不同月份可能得到不同分数

**阈值制的根本困境**：无论如何调阈值，只要验证集和生产环境的正样本率不一致，精度就必然偏离。

### 3.2 Top-K% 排名制的优势

排名制只依赖模型的**排序能力**，不依赖概率值的绝对语义：

| 维度 | 阈值制 | Top-K% 排名制 |
|------|--------|---------------|
| 依赖的能力 | 概率校准 + 排序能力 | **仅排序能力** |
| 对分布偏移的敏感度 | 高（概率值漂移 → 精度崩溃） | **低（排序相对稳定）** |
| 输出数量可控性 | 不可控（取决于概率分布） | **可控（按百分比）** |
| 用户池规模适应性 | 无关 | **自动适应（百分比缩放）** |
| 月度精度可比性 | 差（受正样本率影响） | **好（同比例 ≈ 同精度）** |
| ROC-AUC 利用率 | 部分（只看阈值以上） | **完全利用排序信息** |
| 业务对接 | "模型预测了 N 个"（N 不确定） | "给你前 0.25% 最优用户" |

### 3.3 为什么选择 Top-K% 而非固定 Top-K

| 维度 | 固定 Top-K (如 Top-1000) | Top-K% (如 Top-0.25%) |
|------|:-:|:-:|
| 用户池波动适应性 | 差（池子翻倍，K 不变 → 遗漏机会） | **好（自动按比例缩放）** |
| 精度月度稳定性 | 波动（用户总量变化 → 精度变化） | **稳定（同比例 ≈ 同精度）** |
| 促销月应对 | 不适应（用户暴涨但名单不扩） | **自动扩大输出量** |
| 业务对接 | 简单（"每月 1000 个"） | 需弹性（"这月 800，下月 1200"） |

**结论**：Top-K% 在月度用户池规模波动场景下更鲁棒。配合绝对值上下限兜底，兼顾了自适应性和业务可操作性。

### 3.4 Top-K% 实施方案

#### 3.4.1 核心公式

```
实际输出量 = clamp(总用户数 × K%, 下限, 上限)
```

#### 3.4.2 推荐参数

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| **K%** | **0.25%** | 对应当前 ~1,031 人，精度 86%+ |
| 下限 (MIN_K) | 500 | 保证最少工作量 |
| 上限 (MAX_K) | 3,000 | 超出跟进能力无意义 |
| 最低概率门槛 | 0.30 | 安全护栏：即使 Top-K% 拉到低概率区也截断 |

#### 3.4.3 分层置信等级

基于 Top-K% 内部的排名分层，方便业务按优先级跟进：

| 置信等级 | 排名范围 | 预估精度 | 跟进策略 |
|:--------:|:--------:|:--------:|----------|
| **S 级** | Top 0 ~ 0.10% | 90%+ | 一对一主动外呼，优先跟进 |
| **A 级** | Top 0.10% ~ 0.25% | 80%+ | 标准跟进，短信+外呼 |
| **B 级** | Top 0.25% ~ 0.50% | 65%+ | 批量触达，短信/Push |
| 不输出 | Top 0.50% 以下 | <60% | ROI 不足，不输出 |

> 注：置信等级分界点可按实际业务需求灵活调整。

#### 3.4.4 输出格式

```
排名 | 用户ID | 预测概率 | 置信等级 | 规则层标签
   1 | A***   | 0.9823  | S        | 高确定性
   2 | B***   | 0.9751  | S        | 有购买动作
 ...
 412 | C***   | 0.8234  | A        | 纯意向
 ...
1031 | D***   | 0.6521  | A        | 纯意向
```

#### 3.4.5 代码改动清单

| 文件 | 改动 | 说明 |
|------|------|------|
| `config/feature_list.py` | 新增 `RANKING_CONFIG` | K%、上下限、置信等级配置 |
| `train_pipline.py` | 新增 Top-K% 评估报告 | 训练后输出各 K% 级别的 Precision/Recall |
| `src/models/model_lgb.py` | 新增 `predict_topk_pct()` 方法 | 按百分比截取 + 安全门槛 |
| `src/pipeline/predict_common.py` | 输出改为排名制格式 | 含置信等级、规则层标签 |

#### 3.4.6 RANKING_CONFIG 配置定义

```python

    'enabled': True,
    'top_k_pct': 0.0025,      # Top 0.25%
    'min_k': 500,              # 下限
```

## 四、辅助优化项

### 4.1 F1：最终模型添加 Early Stopping

**问题**：`model_lgb.py:225-229` 最终训练跑满 1000 轮无 early stopping。

**方案**：从 Optuna CV 结果中提取最佳迭代数，作为最终训练上限。

```python
# 在 objective() 中记录最佳迭代数
best_n_rounds = len(cv_results['valid auc-mean'])

# 最终训练时使用（额外加 10% 余量，因为全量数据比 CV 单折多）
self.model = lgb.train(
    best_params,
    train_data,
    num_boost_round=int(best_n_rounds * 1.1),
)
```

**预期收益**：减少 50%+ 多余树，降低过拟合。

### 4.2 F2：repeat_view_ratio 进一步抑制

**问题**：log1p 后仍占 43.92%，需要更强的压缩。

**方案**：双重压缩（sqrt + log1p）

```python
# 当前 (E9): 只做 log1p
fe['repeat_view_ratio'] = np.log1p(fe['repeat_view_ratio'])

# 改为双重压缩: sqrt 先压缩极端值，再 log1p 进一步平滑
raw_ratio = np.expm1(fe['view_detail_cnt']) / (fe['unique_items_viewed'] + 1)
fe['repeat_view_ratio'] = np.log1p(np.sqrt(raw_ratio))
```

**目标**：将重要性从 43% 降至 20% 以下，释放其他特征的学习空间。

### 4.3 F3：阈值搜索下限提升（兼容模式保留）

即使主输出改为排名制，保留阈值制作为兜底/对比。但需修正搜索范围：

```python
# 当前 (E8)
threshold_range = np.arange(0.10, 0.91, 0.01)

# 修改为
threshold_range = np.arange(0.30, 0.91, 0.01)  # 下限提升到 0.30
```

**原因**：[0.10, 0.30) 在测试集上精度仅 18-32%，属于噪声区，不应被阈值搜索选中。

### 4.4 R2（可选）：Isotonic 概率校准

即使采用排名制，概率校准也有助于排序质量的跨月稳定性：

```python
from sklearn.isotonic import IsotonicRegression

# 在验证集上拟合校准器
calibrator = IsotonicRegression(out_of_bounds='clip')
calibrator.fit(val_probs, y_val)

# 预测时校准
probs_calibrated = calibrator.transform(raw_probs)
```

### 4.5 R3（可选）：时间衰减权重

训练集全是 8 月数据，越靠近 9-10 月的行为应权重越高：

```python
days_from_latest = (max_date - train_df['last_action_date']).dt.days
time_weight = np.exp(-0.02 * days_from_latest)  # 半衰期约 35 天
sample_weight = sample_weight * time_weight
```

## 六、总结

### 6.1 核心结论

1. **模型排序能力已经很强**（ROC-AUC 0.9927），不需要大改模型结构
2. **问题出在输出策略**：阈值制对正样本率偏移（6.77% → 1.10%）极度敏感
3. **Top-K% 排名制是最优解**：直接利用排序能力，对分布偏移天然免疫，自适应用户池规模变化
4. **实测验证**：Top 0.25%（≈1,000 人）精度 86%+，远优于阈值制的 48%
5. **辅助修复**：Early Stopping + 特征压缩进一步巩固泛化能力

### 6.2 一句话总结

> **不是模型不行，是阈值制不适合本场景。改用 Top-K% 排名制后，精度从 48% 提升到 86%+，且自适应用户池规模变化。**
