## 1. 概述

### 1.1 服务简介

终端商机挖掘预测服务是基于用户行为数据的机器学习预测系统，旨在识别具有高购买意向的潜在客户。该服务通过分析用户在广东移动终端商城的浏览、点击、登录、试算等行为，预测用户的购买概率，为精准营销提供数据支撑。

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| 购买意向预测 | 根据用户行为日志预测购买概率 |
| 批量处理 | 支持单用户或多用户批量预测 |
| 阈值自定义 | 支持自定义判定阈值 |
| 特征解释 | 可选返回特征详情用于分析 |

### 1.3 技术规格

- **框架**: FastAPI
- **模型**: LightGBM
- **特征数量**: 35个
- **响应格式**: JSON
- **编码**: UTF-8

## 3. 认证方式

### 3.1 API Key 认证

本服务采用 **API Key** 方式进行身份认证。所有需要认证的接口必须在请求头中携带有效的 API Key。

**认证头格式**:
```http
X-API-Key: <your-api-key>
```

### 3.2 获取 API Key

| 环境 | 获取方式 |
|------|----------|
| 开发环境 | 默认密钥: `dev-api-key-change-in-production` |
| 生产环境 | 使用密钥生成工具或联系系统管理员申请 |

**生产环境密钥生成** (推荐):

```bash
# 生成密钥并显示
python generate_api_key.py

# 生成密钥并自动更新 .env 文件
python generate_api_key.py --update

# 生成密钥并备份旧配置
python generate_api_key.py --update --backup

# 自定义密钥长度 (默认48，最小32)
python generate_api_key.py --length 64
```

### 3.3 认证失败响应

当 API Key 缺失或无效时，返回 HTTP 401 错误：

```json
{
  "success": false,
  "error": {
    "code": "UNAUTHORIZED",
    "message": "API Key认证失败",
    "detail": "请在请求Header中提供有效的X-API-Key"
  }
}
```

### 3.4 安全建议

- **不要**在客户端代码中硬编码 API Key
- **不要**在公共代码仓库中提交 API Key
- **定期**轮换生产环境的 API Key
- 使用 HTTPS 传输，防止 Key 被截获

## 4. API 接口详情

### 4.1 预测接口 `POST /api/v1/predict`

根据用户行为日志数据，预测用户的购买意向。

#### 请求参数

**Headers**:
| 名称 | 类型 | 必填 | 说明 |
|------|------|------|------|
| X-API-Key | string | ✅ | API认证密钥 |
| Content-Type | string | ✅ | 固定为 `application/json` |

**Body (JSON)**:

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| user_actions | array | ✅ | 用户行为数据列表 (至少1条，最多10000条) |
| threshold | float | ❌ | 自定义判定阈值 (0-1)，不传则使用模型默认值 |
| return_features | boolean | ❌ | 是否返回特征详情，默认 false |

**user_actions 数组元素结构**:

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| user_id | string | ✅ | 用户唯一标识 | "USER_001" |
| identifier | string | ✅ | 事件标识符 | "eventClick" |
| trigger_time | string | ✅ | 触发时间 (YYYYMMDDHHMMSS) | "20250801100001" |
| target | int | ❌ | 标签 (预测时可不传) | 2 |
| page_name | string | ❌ | 页面名称 | "广东移动终端商城" |
| page_url | string | ❌ | 页面URL | "URL_A" |
| platform_type | string | ❌ | 平台类型 | "APP" |
| area_name | string | ❌ | 区域名称 | "宫格区" |
| sub_area_name | string | ❌ | 子区域名称 | "-" |
| traffic_slot_name | string | ❌ | 流量位名称 | "华为" |
| sub_traffic_slot_name | string | ❌ | 子流量位名称 | "P001" |
| current_item_name | string | ❌ | 当前商品名称 | "华为Mate70" |
| current_item_price | float | ❌ | 当前商品价格 | 7999.0 |
| p_code | string | ❌ | 产品编码 | "P001" |
| item_price | float | ❌ | 商品价格 | 7999.0 |
| item_name | string | ❌ | 商品名称 | "华为Mate70" |
| coupon_name | string | ❌ | 优惠券名称 | "-" |
| process_step | string | ❌ | 办理步骤 | "立即购买" |
| interface_name | string | ❌ | 接口名称 | "INF_01" |
| source_page | string | ❌ | 来源页面 | "HOME" |
| source_area | string | ❌ | 来源区域 | "ZONE_1" |
| cart_count | int | ❌ | 加购数量 | 1 |
| login_type | string | ❌ | 登录方式 | "一键登录" |
| phone_seq | string | ❌ | 手机序列号 | "1001" |

**事件标识符 (identifier) 取值**:

| 值 | 意图等级 | 说明 |
|----|---------|------|
| zdscH5_PageView | 1 | 页面浏览 |
| eventClick | 2 | 点击事件 |
| zdscLogin | 3 | 用户登录 |
| bussinessProcessing | 4 | 业务办理 (试算) |

**成功响应 (HTTP 200)**:


| 字段 | 类型 | 说明 |
|------|------|------|

## 5. 数据结构定义

### 5.1 用户行为日志 (UserBehaviorLog)

```typescript
interface UserBehaviorLog {
  user_id: string;          // 必填: 用户唯一标识
  identifier: string;       // 必填: 事件标识符
  trigger_time: string;     // 必填: 触发时间 (YYYYMMDDHHMMSS)
  target?: number;          // 可选: 标签 (1=已购, 2=未购)
  page_name?: string;       // 可选: 页面名称
  page_url?: string;        // 可选: 页面URL
  platform_type?: string;   // 可选: 平台类型 (APP/Web等)
  area_name?: string;       // 可选: 区域名称
  item_name?: string;       // 可选: 商品名称
  item_price?: number;      // 可选: 商品价格
  process_step?: string;    // 可选: 办理步骤
  login_type?: string;      // 可选: 登录方式
  // ... 其他可选字段
}
```

### 5.2 预测请求 (PredictRequest)

```typescript
interface PredictRequest {
  user_actions: UserBehaviorLog[];  // 必填: 行为数据列表 (1-10000条)
  threshold?: number;       // 可选: 自定义阈值 (0-1)
  return_features?: boolean; // 可选: 是否返回特征 (默认false)
}
```

### 5.3 预测响应 (PredictResponse)

```typescript
interface PredictResponse {
  success: boolean;
  message: string;
  threshold_used: number;
  total_users: number;
  high_intent_count: number;
  predictions: UserPrediction[];
}

interface UserPrediction {
  user_id: string;
  intent_label: "1" | "2";  // "1"=高意向, "2"=低意向
  intent_probability: number;
  features?: Record<string, number | string>;
}
```

### 5.4 错误响应 (ErrorResponse)

```typescript
interface ErrorResponse {
  success: false;
  error: {
    code: string;
    message: string;
    detail?: string;
  };
}
```

```python
import requests
```

#### 自定义批量预测示例

如需自定义批量预测逻辑，可参考以下代码：

```python
import pandas as pd
import requests
from typing import List, Dict

def batch_predict_from_csv(csv_path: str, api_url: str, api_key: str) -> pd.DataFrame:
    """
    从CSV文件批量预测

    Args:
        csv_path: CSV文件路径
        api_url: API地址
        api_key: API密钥

    Returns:
        pd.DataFrame: 预测结果
    """
    # 读取CSV
    df = pd.read_csv(csv_path)

    # 转换为API格式
    actions = df.to_dict(orient='records')

    # 如果数据量超过单次限制，分批处理
    batch_size = 5000
    all_predictions = []

    for i in range(0, len(actions), batch_size):
        batch = actions[i:i+batch_size]

        response = requests.post(
            f"{api_url}/api/v1/predict",
            headers={
                "Content-Type": "application/json",
                "X-API-Key": api_key
            },
            json={"user_actions": batch}
        )

        if response.status_code == 200:
            result = response.json()
            all_predictions.extend(result['predictions'])
        else:
            print(f"批次 {i//batch_size + 1} 失败: {response.text}")

    # 转换为DataFrame
    return pd.DataFrame(all_predictions)


# 使用示例
if __name__ == "__main__":
    results_df = batch_predict_from_csv(
        csv_path="data/raw/predict_data.csv",
        api_url="http://localhost:8000",
        api_key="dev-api-key-change-in-production"
    )

    # 保存结果
    results_df.to_csv("predictions_result.csv", index=False)
    print(f"预测完成，共 {len(results_df)} 条结果")
```

```java
            """;

        // 发送请求
        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create(API_URL + "/api/v1/predict"))
            .header("Content-Type", "application/json")
            .header("X-API-Key", API_KEY)
            .POST(HttpRequest.BodyPublishers.ofString(requestBody))
            .build();

        HttpResponse<String> response = client.send(
            request,
            HttpResponse.BodyHandlers.ofString()
        );

        System.out.println("Status: " + response.statusCode());
        System.out.println("Response: " + response.body());
    }
}
```

## 8. 最佳实践

### 8.1 数据质量

1. **时间格式**: 确保 `trigger_time` 严格遵循 `YYYYMMDDHHMMSS` 格式
2. **时序完整**: 提供用户完整的行为序列，而非单条日志
3. **字段填充**: 尽可能提供完整的可选字段，提高预测准确性
4. **数据排序**: 按时间顺序排列日志记录

### 8.2 性能优化

1. **批量请求**: 将同一用户的多条日志合并为一次请求
2. **分批处理**: 大量数据时，按 5000 条/批次分批请求
3. **连接复用**: 使用 HTTP 连接池，复用 TCP 连接
4. **异步调用**: 高并发场景使用异步 HTTP 客户端

### 8.3 错误处理

```python
try:
    result = predict_intent(user_actions_data)
except requests.exceptions.HTTPError as e:
    if e.response.status_code == 401:
        print("认证失败，请检查API Key")
    elif e.response.status_code == 422:
        print(f"数据格式错误: {e.response.json()}")
    elif e.response.status_code == 503:
        print("服务暂不可用，请稍后重试")
    else:
        print(f"请求失败: {e}")
except requests.exceptions.ConnectionError:
    print("连接失败，请检查服务地址")
```

### 8.4 阈值选择指南

| 场景 | 推荐阈值 | 说明 |
|------|----------|------|
| 高精准营销 | 0.7-0.8 | 减少无效触达，提高转化率 |
| 均衡策略 | 0.5-0.6 | 平衡精准度和覆盖度 |
| 广泛覆盖 | 0.3-0.4 | 最大化潜在客户覆盖 |

### 8.5 CSV 批量预测最佳实践

1. **使用 api_pipeline.py**: 项目提供的批量预测脚本支持自动分批、重试、进度显示
2. **数据预处理**: 确保 CSV 文件包含必要字段 (user_id, identifier, trigger_time)
3. **批次大小**: 建议 1000-5000 条/批次，避免超时
4. **输出一致性**: `api_pipeline.py` 输出格式与 `predict_pipline.py` 完全一致
5. **环境变量**: 使用 `.env` 文件管理 API_KEY，避免在命令行暴露密钥

## 9. 常见问题

### Q1: 为什么预测结果为空？

**可能原因**:
1. 所有日志的 `trigger_time` 格式不正确
2. 所有日志的 `identifier` 为结果事件 (orderSuccess)
3. 用户ID全部缺失

**解决方案**:
- 检查时间格式是否为 YYYYMMDDHHMMSS
- 确保包含行为事件 (eventClick, zdscLogin, bussinessProcessing)

### Q2: 如何提高预测准确性？

**建议**:
1. 提供更完整的用户行为序列
2. 确保关键字段有值 (item_name, item_price, process_step, login_type)
3. 包含用户的登录和试算行为

### Q3: 单次请求最大支持多少数据？

**限制**:
- 单次最多 10,000 条日志记录
- 超出限制返回 413 错误

### Q4: API Key 如何安全存储？

**建议**:
- 开发环境: 使用 `.env` 文件 (不要提交到版本控制)
- 生产环境: 使用 `generate_api_key.py` 生成强密钥，通过环境变量或密钥管理服务配置

```bash
# 生产环境推荐流程
python generate_api_key.py --update --backup
```

### Q5: 如何使用 api_pipeline.py 进行批量预测？

**使用方法**:
```bash
# 1. 设置 API 密钥
export API_KEY=$(grep '^API_KEY=' .env | cut -d '=' -f2)

# 2. 执行批量预测
python api_pipeline.py --input data/raw/api_batch_test.csv

# 3. 查看结果
cat data/processed/marketing_list.csv
```

**注意**: 输出格式与 `predict_pipline.py` 完全一致，包含 `user_id,intent_label,intent_probability` 三列。

### Q6: 如何监控API服务状态？

**方案**:
1. 定期调用 `/api/v1/health` 端点
2. 配置健康检查告警 (status != "healthy")
3. 监控响应时间和错误率

### Q7: api_pipeline.py 和 predict_pipline.py 有什么区别？

| 特性 | predict_pipline.py | api_pipeline.py |
|------|-------------------|-----------------|
| 运行方式 | 本地直接调用模型 | 通过 API 远程调用 |
| 依赖环境 | 需要完整训练环境 | 仅需 requests 库 |
| 适用场景 | 开发测试、大批量离线预测 | 生产环境、API 集成测试 |
| 输出格式 | 相同 | 相同 |
| 输出路径 | data/processed/marketing_list.csv | data/processed/marketing_list.csv |
