  二、根因诊断（按影响排序）

  根因 #1：正样本率分布偏移（核心问题）

  这是 全部精度崩溃的第一驱动因素：

  ┌──────────┬─────────────┬──────────────┬───────┐
  │          │ 验证集(9月) │ 测试集(10月) │ 倍差  │
  ├──────────┼─────────────┼──────────────┼───────┤
  │ 正样本   │ 2,361       │ 4,546        │       │
  ├──────────┼─────────────┼──────────────┼───────┤
  │ 负样本   │ 32,517      │ 407,765      │       │
  ├──────────┼─────────────┼──────────────┼───────┤
  │ 正样本率 │ 6.77%       │ 1.10%        │ 6.15x │
  └──────────┴─────────────┴──────────────┴───────┘

  验证集正样本率是测试集的 6 倍。

  原因在 data_extra_withdata.py：
  - 8-9月数据：50% 一致性哈希采样，采样后正样本率 ~7%（被人为富集）
  - 10月数据：回测用户名单全量匹配，反映真实世界的 ~1% 正样本率

  这意味着：在验证集上阈值 0.10 看到的是"每 100 个预测正里有 85 个真正"的环境，到了测试集变成"每 100 个预测正里只有 48
  个真正"——因为负样本密度翻了 6 倍。

  数学关系：在相同模型排序能力下，如果正样本率从 p1 变成 p2，精度大致按 Precision_new ≈ Precision_old × (p2/p1)
  缩放。85.31% × (1.10/6.77) ≈ 13.9%（实际 48.28% 好于此，说明模型确实有区分力）。

  根因 #2：最终模型训练缺少 Early Stopping

  model_lgb.py:225-229 中，Optuna 找到最佳超参后的最终训练：

  self.model = lgb.train(
      best_params,
      train_data,
      num_boost_round=1000   # ← 无 early stopping，无 valid_sets
  )

  Optuna 内部 CV 用了 early_stopping(30)，但最终全量拟合时跑满 1000 轮。这是一个严重的过拟合源——Optuna 选的最佳迭代次数约
   200-400 轮，但最终模型跑了 1000 轮，多出的树只在拟合训练集噪声。

  根因 #3：repeat_view_ratio 特征垄断

  repeat_view_ratio    43.92%   ← 近半重要性
  avg_intent_level      9.93%
  view_detail_cnt       9.86%

  单特征 43.92% 意味着模型本质上是一个重复浏览率分类器。虽然已做了 log1p 压缩（E9），但效果不够。此特征如果在 8-9 月→10
  月之间分布漂移（用户行为季节性变化），会直接拖垮整个模型。

  根因 #4：E8 区间 [0.10, 0.30) 在测试集上失效

  └──────────┴────────────┴─────────────┘

  验证集上 >50% 看似有效，但测试集上仅 25%（低于随机）。这说明 低概率区间的信号在跨月后严重衰减，阈值 0.10
  捡起了大量噪声样本。

  根因 #5：正样本概率分布漂移

  ┌────────────────────────┬────────┬────────┐

  - 10 月的正样本行为模式与 8 月训练数据有差异
  - 10月测试集来源是回测名单，其正样本特征分布可能与训练集不同

  三、优化方案（按优先级排序）

  P-Critical：修复分布对齐问题

  问题：验证集和测试集正样本率差 6 倍，导致阈值无法迁移。

  方案A（推荐）：对验证集做下采样，对齐真实正样本率

  在 train_pipline.py 中，对 9 月验证集的负样本进行下采样，使其正样本率与 10
  月一致（~1%）。或者反过来，保持验证集不变，但在阈值搜索时加入先验校正：

  # 方案：在阈值搜索前，用验证集的正样本率和真实正样本率做校正
  # 校正后的精度 = precision_val * (real_pos_rate / val_pos_rate)
  REAL_POS_RATE = 0.011  # 真实环境约 1.1%

  方案B：改用排名制替代阈值制

  不用固定阈值，改为"取预测概率 Top-K% 的用户"。这对分布偏移具有天然鲁棒性：

  # 例：取预测概率 Top 3% 的用户作为高意向
  target_rate = 0.03
  threshold = np.percentile(probs, (1 - target_rate) * 100)

  P0：最终模型添加 Early Stopping

  在 model_lgb.py 的 auto_train 方法中，最终训练需要加入验证集+early stopping：

  # 用 Optuna CV 得到的最佳迭代数作为上限
  best_n_rounds = len(cv_results['valid auc-mean'])  # 从 CV 获取

  self.model = lgb.train(
      best_params,
      train_data,
      num_boost_round=best_n_rounds,   # 使用 CV 最佳轮次
      # 或者传入 valid_sets + early_stopping
  )

  预期效果：减少 30-50% 的多余树，降低过拟合，对精度和 F1 的泛化都有直接提升。

  P1：repeat_view_ratio 进一步抑制

  当前 log1p 不够，建议：

  方案1：双重压缩
  fe['repeat_view_ratio'] = np.log1p(np.sqrt(fe['repeat_view_ratio_raw']))

  方案2：分位数截断 + 归一化
  cap = fe['repeat_view_ratio'].quantile(0.95)
  fe['repeat_view_ratio'] = fe['repeat_view_ratio'].clip(upper=cap) / cap

  方案3：CEGB 惩罚（代码已有但禁用，可针对此特征单独启用）

  目标：将该特征重要性从 43% 降到 20% 以下，迫使模型学习更多元的信号。

  P2：阈值提升 + E8 区间缩窄

  当前阈值 0.10 在测试集上导致大量 FP。建议：

  1. 将 E8 搜索下界从 0.10 提高到 0.20 或 0.30——[0.10, 0.20) 区间在测试集上精度仅 18-26%，属于噪声区
  2. 在阈值搜索中加入精度下限约束：
  if metrics['precision'] < 0.50:  # 新增：精度不低于 50%
      continue

  P3：概率校准（Isotonic Regression）

  这是 docs 中已规划但未实施的 P1a。在验证集上训练校准器，使概率输出在跨月场景下更稳定：

  from sklearn.isotonic import IsotonicRegression
  calibrator = IsotonicRegression(out_of_bounds='clip')
  calibrator.fit(val_probs, y_val)
  # 测试时
  test_probs_calibrated = calibrator.transform(test_probs)

  P4：时间衰减权重（Time Decay）

  训练集全是 8 月数据，但真实预测目标是 10 月。越靠近 9-10 月的样本应该权重越高：

  # 按时间给予权重：8月初权重0.5，8月底权重1.0
  days_from_latest = (max_date - train_df['last_action_date']).dt.days
  time_weight = np.exp(-0.02 * days_from_latest)  # 半衰期约35天
  sample_weight = sample_weight * time_weight

  P5：交叉验证策略升级

  当前 Optuna 用 3-fold 随机分层 CV，但不包含时间信息。建议改为时序交叉验证：

  from sklearn.model_selection import TimeSeriesSplit
  # 或自定义：8月前半段训练 → 8月后半段验证

  这样 CV 的评估更贴近实际的"用历史预测未来"场景。

  五、总结

  核心结论：模型的排序能力已经很好（ROC-AUC 0.9927），真正的瓶颈不是"模型不行"，而是 阈值在不同正样本率下无法迁移。

  最高优先级的改进是：

  二、根因诊断（按影响排序）

  根因 #1：正样本率分布偏移（核心问题）

  这是 全部精度崩溃的第一驱动因素：

  ┌──────────┬─────────────┬──────────────┬───────┐
  │          │ 验证集(9月) │ 测试集(10月) │ 倍差  │
  ├──────────┼─────────────┼──────────────┼───────┤
  │ 正样本   │ 2,361       │ 4,546        │       │
  ├──────────┼─────────────┼──────────────┼───────┤
  │ 负样本   │ 32,517      │ 407,765      │       │
  ├──────────┼─────────────┼──────────────┼───────┤
  │ 正样本率 │ 6.77%       │ 1.10%        │ 6.15x │
  └──────────┴─────────────┴──────────────┴───────┘

  验证集正样本率是测试集的 6 倍。

  原因在 data_extra_withdata.py：
  - 8-9月数据：50% 一致性哈希采样，采样后正样本率 ~7%（被人为富集）
  - 10月数据：回测用户名单全量匹配，反映真实世界的 ~1% 正样本率

  这意味着：在验证集上阈值 0.10 看到的是"每 100 个预测正里有 85 个真正"的环境，到了测试集变成"每 100 个预测正里只有 48
  个真正"——因为负样本密度翻了 6 倍。

  数学关系：在相同模型排序能力下，如果正样本率从 p1 变成 p2，精度大致按 Precision_new ≈ Precision_old × (p2/p1)
  缩放。85.31% × (1.10/6.77) ≈ 13.9%（实际 48.28% 好于此，说明模型确实有区分力）。

  根因 #2：最终模型训练缺少 Early Stopping

  model_lgb.py:225-229 中，Optuna 找到最佳超参后的最终训练：

  self.model = lgb.train(
      best_params,
      train_data,
      num_boost_round=1000   # ← 无 early stopping，无 valid_sets
  )

  Optuna 内部 CV 用了 early_stopping(30)，但最终全量拟合时跑满 1000 轮。这是一个严重的过拟合源——Optuna 选的最佳迭代次数约
   200-400 轮，但最终模型跑了 1000 轮，多出的树只在拟合训练集噪声。

  根因 #3：repeat_view_ratio 特征垄断

  repeat_view_ratio    43.92%   ← 近半重要性
  avg_intent_level      9.93%
  view_detail_cnt       9.86%

  单特征 43.92% 意味着模型本质上是一个重复浏览率分类器。虽然已做了 log1p 压缩（E9），但效果不够。此特征如果在 8-9 月→10
  月之间分布漂移（用户行为季节性变化），会直接拖垮整个模型。

  根因 #4：E8 区间 [0.10, 0.30) 在测试集上失效

  ┌──────────┬────────────┬─────────────┐
  │          │   验证集   │   测试集    │
  ├──────────┼────────────┼─────────────┤
  │ 正样本   │ 167 (7.1%) │ 647 (14.2%) │
  ├──────────┼────────────┼─────────────┤
  │ 负样本   │ 127        │ 1,944       │
  ├──────────┼────────────┼─────────────┤
  │ 区间精度 │ 56.8%      │ 25.0%       │
  └──────────┴────────────┴─────────────┘

  验证集上 >50% 看似有效，但测试集上仅 25%（低于随机）。这说明 低概率区间的信号在跨月后严重衰减，阈值 0.10
  捡起了大量噪声样本。

  根因 #5：正样本概率分布漂移

  ┌────────────────────────┬────────┬────────┐
  │                        │ 验证集 │ 测试集 │
  ├────────────────────────┼────────┼────────┤

  - 10 月的正样本行为模式与 8 月训练数据有差异
  - 10月测试集来源是回测名单，其正样本特征分布可能与训练集不同

  三、优化方案（按优先级排序）

  P-Critical：修复分布对齐问题

  问题：验证集和测试集正样本率差 6 倍，导致阈值无法迁移。

  方案A（推荐）：对验证集做下采样，对齐真实正样本率

  在 train_pipline.py 中，对 9 月验证集的负样本进行下采样，使其正样本率与 10
  月一致（~1%）。或者反过来，保持验证集不变，但在阈值搜索时加入先验校正：

  # 方案：在阈值搜索前，用验证集的正样本率和真实正样本率做校正
  # 校正后的精度 = precision_val * (real_pos_rate / val_pos_rate)
  REAL_POS_RATE = 0.011  # 真实环境约 1.1%

  方案B：改用排名制替代阈值制

  不用固定阈值，改为"取预测概率 Top-K% 的用户"。这对分布偏移具有天然鲁棒性：

  # 例：取预测概率 Top 3% 的用户作为高意向
  target_rate = 0.03
  threshold = np.percentile(probs, (1 - target_rate) * 100)

  P0：最终模型添加 Early Stopping

  在 model_lgb.py 的 auto_train 方法中，最终训练需要加入验证集+early stopping：

  # 用 Optuna CV 得到的最佳迭代数作为上限
  best_n_rounds = len(cv_results['valid auc-mean'])  # 从 CV 获取

  self.model = lgb.train(
      best_params,
      train_data,
      num_boost_round=best_n_rounds,   # 使用 CV 最佳轮次
      # 或者传入 valid_sets + early_stopping
  )

  预期效果：减少 30-50% 的多余树，降低过拟合，对精度和 F1 的泛化都有直接提升。

  P1：repeat_view_ratio 进一步抑制

  当前 log1p 不够，建议：

  方案1：双重压缩
  fe['repeat_view_ratio'] = np.log1p(np.sqrt(fe['repeat_view_ratio_raw']))

  方案2：分位数截断 + 归一化
  cap = fe['repeat_view_ratio'].quantile(0.95)
  fe['repeat_view_ratio'] = fe['repeat_view_ratio'].clip(upper=cap) / cap

  方案3：CEGB 惩罚（代码已有但禁用，可针对此特征单独启用）

  目标：将该特征重要性从 43% 降到 20% 以下，迫使模型学习更多元的信号。

  P2：阈值提升 + E8 区间缩窄

  当前阈值 0.10 在测试集上导致大量 FP。建议：

  1. 将 E8 搜索下界从 0.10 提高到 0.20 或 0.30——[0.10, 0.20) 区间在测试集上精度仅 18-26%，属于噪声区
  2. 在阈值搜索中加入精度下限约束：
  if metrics['precision'] < 0.50:  # 新增：精度不低于 50%
      continue

  P3：概率校准（Isotonic Regression）

  这是 docs 中已规划但未实施的 P1a。在验证集上训练校准器，使概率输出在跨月场景下更稳定：

  from sklearn.isotonic import IsotonicRegression
  calibrator = IsotonicRegression(out_of_bounds='clip')
  calibrator.fit(val_probs, y_val)
  # 测试时
  test_probs_calibrated = calibrator.transform(test_probs)

  P4：时间衰减权重（Time Decay）

  训练集全是 8 月数据，但真实预测目标是 10 月。越靠近 9-10 月的样本应该权重越高：

  # 按时间给予权重：8月初权重0.5，8月底权重1.0
  days_from_latest = (max_date - train_df['last_action_date']).dt.days
  time_weight = np.exp(-0.02 * days_from_latest)  # 半衰期约35天
  sample_weight = sample_weight * time_weight

  P5：交叉验证策略升级

  当前 Optuna 用 3-fold 随机分层 CV，但不包含时间信息。建议改为时序交叉验证：

  from sklearn.model_selection import TimeSeriesSplit
  # 或自定义：8月前半段训练 → 8月后半段验证

  这样 CV 的评估更贴近实际的"用历史预测未来"场景。
