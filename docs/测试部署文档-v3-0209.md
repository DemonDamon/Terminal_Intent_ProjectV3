## 2. 数据处理

### 2.1 数据准备

将原始数据文件放置到 `data/raw/` 目录下。

```bash
# 查看数据目录
ls -la data/raw/
```

### 2.2 数据分流处理 (大文件场景)

当原始数据文件较大时，使用 `data_extra_withdata.py` 进行分流处理。

```bash
# 执行数据分流
# 功能：将大文件按月份分割为训练集(8-9月)和预测集(10月)
python data_extra_withdata.py

# 构建回测数据集
python data_extra_backtest.py
```

**输出文件**:

- `data/raw/train_data_89.csv` - 8-9月训练数据 (50%采样)
- `data/raw/predict_data_10.csv` - 10月预测数据

### 2.3 数据采样 (可选)

对于超大文件，可使用 `data_extra_train.py` 进行采样。

```bash
# 执行数据采样 (默认25%采样)
python data_extra_train.py
```

### 6.2 批量测试

#### 方式一: 使用 api_pipeline.py 脚本 (推荐)

从CSV文件批量预测，适用于大规模数据测试。

**步骤1: 配置 API 密钥**

```bash
# 生成密钥并更新 .env (推荐)
python generate_api_key.py --update
```

**注意**: 如果 .env 文件来自 Windows 系统，需先转换换行符:

```bash
sed -i 's/\r$//' .env
```

**步骤2: 执行批量预测**

```bash
# 使用默认配置 (读取 data/raw/api_batch_test.csv)
python api_pipeline.py

# 指定输入输出文件
python api_pipeline.py --input data/raw/api_batch_test.csv --output data/processed/result.csv

# 自定义批次大小和阈值
python api_pipeline.py --batch-size 500 --threshold 0.6

# 仅检查配置，不执行 (调试用)
python api_pipeline.py --dry-run
```

**输出结果**: `data/processed/marketing_list.csv`

## 10. 常见问题

### Q1: 模型文件找不到

**解决**: 确保先执行训练脚本

```bash
python train_pipline.py
ls -la models/
```

### Q2: API响应时间格式错误

**原因**: `trigger_time` 格式不正确

**解决**: 确保格式为 `YYYYMMDDHHMMSS`，例如 `20250801100001`

### Q3: 端口被占用

**解决**:

```bash
# 查找占用端口的进程
lsof -i :8000

# 更换端口启动
python -m uvicorn api.main:app --host 0.0.0.0 --port 8001
```

### Q4: API认证失败 (401错误)

**原因**: API_KEY 配置不正确或包含隐藏字符

**解决**:

```bash
# 1. 检查 .env 文件是否有隐藏字符 (Windows换行符)
cat -A .env | head -5
# 如果看到 ^M 表示有Windows换行符

# 2. 转换为Unix格式
sed -i 's/\r$//' .env

# 3. 验证配置 (检查密钥长度)
python api_pipeline.py --dry-run

# 4. 重新生成密钥
python generate_api_key.py --update
```

**配置注意事项**:

- .env 文件中 API_KEY 不要加引号: `API_KEY=abc123` ✓
- 等号两边不要有空格: `API_KEY = abc123` ✗
- 确保服务端和客户端使用相同的密钥

### Q5: Docker镜像构建失败

**解决**:

```bash
# 清理后重新构建
docker system prune -f
make build
```
