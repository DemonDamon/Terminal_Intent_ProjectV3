## 一、版本背景与核心问题

### 1.1 v0.5.2 现状

v0.5.2 完成了 P0/P1b/P2a/P2b 四项泛化增强和 PSI 诊断工具建设，10 月测试集结果揭示了关键发现：

| 指标 | 验证集(9月) | 测试集(10月) | 差距 | 严重度 |
|------|:----------:|:----------:|:----:|:------:|
| ROC-AUC | 0.9933 | 0.9927 | -0.0006 | **稳定** |
| KS | 0.9390 | 0.9372 | -0.0018 | **稳定** |
| PR-AUC | 0.9303 | **0.6716** | **-0.2587** | **严重** |
| Precision | 85.31% | **48.28%** | **-37.03pp** | **严重** |
| Recall | 88.52% | 82.27% | -6.25pp | 中等 |
| F1-Score | 0.8688 | **0.6085** | **-0.2603** | **严重** |

**关键发现**：ROC-AUC（0.9927）和 KS（0.9372）在测试集上几乎无退化——**模型的排序能力已充分泛化**。问题不在模型，而在于固定阈值 0.10 在不同正样本率下无法迁移。

### 1.2 根因分析

| # | 根因 | 影响 | 优先级 |
|---|------|------|:------:|
| 1 | 正样本率分布偏移 6.15x (6.77% → 1.10%)，阈值制精度崩溃 | Precision 85% → 48% | **P-Critical** |
| 2 | 最终模型训练跑满 1000 轮，无 Early Stopping | 600+ 棵多余树过拟合 | **P0** |
| 3 | repeat_view_ratio 单特征垄断 43.92% | 模型脆弱性 | **P1** |
| 4 | [0.10, 0.30) 区间在测试集精度仅 18-32% | 阈值搜索噪声 | **P2** |

### 1.3 v0.5.3 目标

本版聚焦输出策略革新与过拟合修复：

1. **R1**：Top-K% 排名制替代阈值制（核心策略变革）
2. **F1**：最终模型 Early Stopping（消除过拟合源）
3. **F2**：repeat_view_ratio 双重压缩（降低特征垄断）
4. **F3**：阈值搜索下限提升（兼容模式优化）

## 三、R1：Top-K% 排名制输出策略

### 3.1 问题

阈值制的隐含前提是：模型输出的概率值在不同环境下具有一致的语义。但实际情况：

- 训练/验证集正样本率 ~7% vs 真实环境 ~1%，相差 6 倍
- LightGBM 输出受 `scale_pos_weight` 影响，并非真实概率
- 特征分布跨月漂移，同一用户不同月份得到不同分数

**根本困境**：无论如何调阈值，只要验证集和生产环境的正样本率不一致，精度就必然偏离。

### 3.2 方案

改用 Top-K% 排名制，只依赖模型的**排序能力**（ROC-AUC 0.99+），不依赖概率值的绝对语义。

| 维度 | 阈值制 | Top-K% 排名制 |
|------|--------|---------------|
| 依赖的能力 | 概率校准 + 排序 | **仅排序能力** |
| 对分布偏移敏感度 | 高 | **低** |
| 输出数量可控性 | 不可控 | **精确可控** |
| 用户池规模适应性 | 无关 | **自动适应** |

### 3.3 核心公式

```
实际输出量 = clamp(总用户数 × K%, 下限, 上限)
```

安全护栏：即使 Top-K% 拉到低概率区也截断（min_prob=0.30）。

### 3.4 具体改动

#### 3.4.1 `config/feature_list.py` — 新增 RANKING_CONFIG

```python
RANKING_CONFIG = {
    'enabled': True,
    'top_k_pct': 0.0025,      # Top 0.25%
    'min_k': 500,              # 下限：保证最少工作量
    'max_k': 3000,             # 上限：超出跟进能力无意义
    'min_prob': 0.30,          # 最低概率门槛（安全护栏）
    'tiers': {
        'S': {'pct_upper': 0.0010, 'desc': '最高置信'},   # Top 0.10%
        'A': {'pct_upper': 0.0025, 'desc': '高置信'},     # Top 0.25%
        'B': {'pct_upper': 0.0050, 'desc': '中置信'},     # Top 0.50%
    },
}
```

#### 3.4.2 `src/models/model_lgb.py` — 新增 predict_topk_pct()

```python
def predict_topk_pct(self, X, ranking_config):
    """
    【R1】Top-K% 排名制预测
    按百分比截取高潜用户，附带安全门槛和置信等级分层。
    """
    probs = self.model.predict(X)
    n_total = len(probs)

    # 计算 K：clamp(总用户数 × K%, 下限, 上限)
    k_raw = int(n_total * ranking_config['top_k_pct'])
    k = max(ranking_config['min_k'], min(ranking_config['max_k'], k_raw))
    k = min(k, n_total)

    # 按概率降序排名
    ranked_indices = np.argsort(probs)[::-1]

    # 安全门槛：截断低于 min_prob 的用户
    min_prob = ranking_config.get('min_prob', 0.30)
    valid_mask = probs[ranked_indices[:k]] >= min_prob
    actual_k = int(valid_mask.sum())
    ranked_indices = ranked_indices[:actual_k]

    # 分层置信等级
    tiers_config = ranking_config.get('tiers', {})
    tiers = []
    for i, idx in enumerate(ranked_indices):
        rank_pct = (i + 1) / n_total
        tier = 'B'
        for tier_name in ['S', 'A', 'B']:
            if tier_name in tiers_config and rank_pct <= tiers_config[tier_name]['pct_upper']:
                tier = tier_name
                break
        tiers.append(tier)

    return ranked_indices, probs, tiers, actual_k
```

## 四、F1：最终模型 Early Stopping

### 4.1 问题

`model_lgb.py` 最终训练阶段：

```python
# v0.5.2（旧）
self.model = lgb.train(
    best_params,
    train_data,
    num_boost_round=1000   # ← 无 early stopping，无 valid_sets
)
```

- Optuna 内部 3-fold CV 使用了 `early_stopping(30)`，实际最优轮次通常在 200-400 轮
- 最终全量拟合时**跑满 1000 轮**，多出 600+ 棵树全在拟合训练集噪声

### 4.2 方案

从 Optuna 最佳 trial 的 CV 结果中提取最优迭代数，加 10% 余量作为最终训练上限。

### 4.3 具体改动

修改文件：`src/models/model_lgb.py`

**1）在 `objective()` 外部初始化记录列表：**

```python
# 【F1】用于记录 Optuna 最佳 trial 的 CV 最优迭代数
best_n_rounds_list = []
```

**2）在 `objective()` 末尾记录每个 trial 的最优迭代数：**

```python
# 【F1】记录每个 trial 的 CV 最优迭代数
n_rounds = len(cv_results['valid auc-mean'])
best_n_rounds_list.append((trial.number, n_rounds))
```

**3）最终训练时使用 CV 最优迭代数 ×1.1：**

```python
# 【F1】从最佳 trial 提取 CV 最优迭代数，加 10% 余量
best_trial_number = study.best_trial.number
best_n_rounds = next(n for t, n in best_n_rounds_list if t == best_trial_number)
final_n_rounds = int(best_n_rounds * 1.1)
print(f">>> 【F1】CV 最优迭代数: {best_n_rounds}, 最终训练轮次: {final_n_rounds} (×1.1)")

self.model = lgb.train(
    best_params,
    train_data,
    num_boost_round=final_n_rounds
)
```

### 4.4 预期效果

- 最终模型轮次：1000（固定）→ ~220-440（自适应）
- 减少 50%+ 多余树，降低过拟合
- 10% 余量弥补全量数据 vs CV 单折的差异

## 五、F2：repeat_view_ratio 双重压缩

### 5.1 问题

v0.5.2 中 `repeat_view_ratio` 经过 E9 的 `log1p` 压缩后仍占特征重要性 **43.92%**，单特征垄断导致：

1. 模型本质上是"重复浏览率分类器"，脆弱
2. 其他 39 个特征的信号被压制
3. 若该特征跨月分布漂移，直接拖垮整个模型

### 5.2 方案

将单层 `log1p` 压缩改为 `sqrt + log1p` 双重压缩。

### 5.3 具体改动

修改文件：`src/features/unified_fe.py`

```python
# v0.5.2（旧）
fe['repeat_view_ratio'] = np.expm1(fe['view_detail_cnt']) / (fe['unique_items_viewed'] + 1)
fe['repeat_view_ratio'] = np.log1p(fe['repeat_view_ratio'])

# v0.5.3（新）
raw_repeat_ratio = np.expm1(fe['view_detail_cnt']) / (fe['unique_items_viewed'] + 1)
fe['repeat_view_ratio'] = np.log1p(np.sqrt(raw_repeat_ratio))
```

### 5.4 压缩效果对比

| 原始值 | log1p(x) | log1p(sqrt(x)) | 压缩增强倍数 |
|:------:|:--------:|:--------------:|:----------:|
| 1.0 | 0.693 | 0.693 | 1.0x |
| 5.0 | 1.792 | 1.194 | 1.5x |
| 10.0 | 2.398 | 1.498 | 1.6x |
| 50.0 | 3.932 | 2.084 | 1.9x |
| 100.0 | 4.615 | 2.397 | 1.9x |

对极端值（≥10）的压缩力度几乎翻倍。

### 5.5 预期效果

- 特征重要性：43.92% → **≤ 25%**
- 其他中层特征（avg_intent_level, view_detail_cnt, click_to_process_rate）获得更多学习空间
- `revisit_intensity`（= active_days × repeat_view_ratio）同步受到影响，信号更平缓

## 六、F3：阈值搜索下限提升

### 6.1 问题

v0.5.2 中 E8 将阈值搜索下界扩展到 0.10，但 v0.5.2 运行结果显示 [0.10, 0.30) 区间在测试集上：

| | 验证集 | 测试集 |
|---|:---:|:---:|
| 正样本 | 167 (7.1%) | 647 (14.2%) |
| 负样本 | 127 | 1,944 |
| **区间精度** | **56.8%** | **25.0%** |

该区间属于噪声区，不应被阈值搜索选中。

### 6.2 方案

主输出已改为排名制，阈值搜索作为兼容模式保留，但需修正搜索范围。

### 6.3 具体改动

修改文件：`src/models/model_lgb.py`

```python
# v0.5.2（旧）
threshold_range = np.arange(0.10, 0.91, 0.01)

# v0.5.3（新）
threshold_range = np.arange(0.30, 0.91, 0.01)
```

### 6.4 预期效果

- 消除 [0.10, 0.30) 噪声区对阈值搜索的干扰
- 阈值制兼容模式的 Precision 提升（不再选中低精度区间）
