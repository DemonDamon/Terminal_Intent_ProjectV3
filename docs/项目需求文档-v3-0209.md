## 1. 项目概述

### 1.1 项目基本信息

| 属性 | 内容 |
|------|------|
| **项目名称** | 终端商机挖掘预测服务 |
| **项目版本** | V2.0 (API版) |
| **项目代号** | Terminal_Intent_ProjectV2 |
| **业务方** | 广东移动终端商城 |
| **服务形态** | RESTful API + 离线批处理 |
| **技术栈** | Python 3.10 + LightGBM + FastAPI + Docker |

### 1.2 项目背景与目标

#### 业务背景
广东移动终端商城拥有海量用户行为日志数据，包括页面浏览、商品点击、登录行为、购物车操作等。在海量用户中识别高购买意向客户，是精准营销的核心需求。

#### 核心目标
1. **预测用户购买意向** - 基于用户历史行为数据，预测其购买终端设备的可能性
2. **支撑精准营销** - 输出高意向用户名单，供营销团队定向触达
3. **提升营销效率** - 降低无效营销成本，提高转化ROI

#### 业务价值
- 营销精准度提升：从广撒网模式转变为精准触达
- 成本优化：减少对低意向用户的营销投入
- 转化率提升：优先触达高意向用户，提高成交概率

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| **target** | 训练数据中的真实标签。`1`=高意向/已购机用户，`0`=低意向/未购机用户 |
| **intent_label** | 模型预测输出的意向标签。`"1"`=预测为高购买意向，`"2"`=预测为低购买意向 |
| **intent_probability** | 模型输出的购买意向概率，范围 [0, 1]，值越大表示购买意向越高 |
| **threshold** | 判定阈值，概率 ≥ 阈值判定为高意向(label=1)，否则为低意向(label=2) |
| **商机** | 被判定为高购买意向的用户 |
| **特征泄露** | 使用了包含目标信息的特征（如订单成功事件）导致模型过拟合 |
| **特征弱化** | 降低某些强信号特征的影响，使模型学习更稳健的规律 |

## 2. 业务需求

### 2.1 业务场景描述

本服务应用于以下典型场景：

1. **日常营销** - 每日/每周输出高意向用户名单，供营销团队短信/外呼触达
2. **活动营销** - 大促活动前预测潜在购买用户，集中资源触达
3. **实时响应** - 用户浏览过程中实时预测意向，触发即时营销策略

### 2.2 目标用户定义

**预测对象**：广东移动终端商城的活跃用户

**用户特征**：
- 有登录行为或设备标识的用户
- 有终端商城页面访问记录的用户
- 产生过商品浏览、点击、加购等行为的用户

### 2.3 预测目标与标签定义

#### 训练标签 (target)
| 值 | 含义 | 数据来源 |
|----|------|----------|
| `1` | 正样本：高意向/已购机用户 | 历史订单成功用户 |
| `0` | 负样本：低意向/未购机用户 | 有行为但未下单用户 |

#### 预测标签 (intent_label)
| 值 | 含义 | 判定规则 |
|----|------|----------|
| `"1"` | 高购买意向 | intent_probability ≥ threshold |
| `"2"` | 低购买意向 | intent_probability < threshold |

#### 意向概率 (intent_probability)
- **取值范围**: [0, 1]
- **含义**: 用户购买终端设备的概率预估
- **输出精度**: 保留6位小数

### 2.4 业务约束条件

| 约束项 | 要求 | 说明 |
|--------|------|------|
| 商机占比上限 | ≤ 50% | 避免商机名单过大导致营销资源分散 |
| 阈值搜索范围 | 0.3 ~ 0.9 | 避免极端阈值导致无效预测 |
| 优化目标 | F1-Score 最大化 | 平衡准确率和召回率 |

## 3. 功能需求

### 3.1 模型训练功能

#### 功能描述
支持基于历史数据训练购买意向预测模型，包含自动超参数调优和阈值优化。

#### 入口文件
`train_pipline.py`

#### 核心能力

| 能力项 | 实现方式 | 配置参数 |
|--------|----------|----------|
| 自动超参数调优 | Optuna贝叶斯优化 | `n_trials=8` (可调整至15-30) |
| 自动阈值优化 | 网格搜索 0.3~0.9 | 步长 0.01，目标 F1 最大化 |
| 业务约束 | 商机占比 ≤ 50% | 硬约束，超出则跳过该阈值 |
| 特征弱化策略 | 对数变换 | 对购机直接相关特征降权 |
| 交叉验证 | 3折分层采样 | `stratified=True` |
| 早停机制 | 30轮无提升停止 | `stopping_rounds=30` |

```python
def decode_phone(text):
    try:
        text_str = str(text).strip()
        if pd.isna(text_str) or text_str in ['', 'nan', 'None']:
            return "unknown_user"
        # 处理科学计数法

            text_str = "{:.0f}".format(float(text_str))
        if text_str.endswith('.0'):

        return text_str  # 解码失败返回原值
```

## 5. 特征工程规格

| cnt_bussProcessing | int | 业务办理次数 | `(identifier == 'bussinessProcessing').sum()` |
| total_actions | int | 总行为次数 | `cnt_eventClick + cnt_bussProcessing` |
| click_buy_now_cnt | int | 点击购买按钮次数 | 匹配关键词：立即购买\|立即申请\|去结算\|立即下单\|提交订单 |

| 特征名 | 类型 | 说明 | 计算逻辑 |

| recent_5_avg_intent | float | 最近5次平均意图 | 最近5条记录的意图等级均值 |

### 5.2 特征泄露防护机制

#### 泄露源识别
以下事件属于"结果型"事件，在特征计算前必须剔除：

```python
LEAKY_EVENTS = [
    'orderSuccess',        # 订单成功
    'server_orderSuccess', # 服务端订单成功
    '支付成功',             # 支付成功
    '办理成功'              # 办理成功
]
```

#### 防护实现
```python
# 创建用于特征计算的"纯净"数据集
df_features = df[~df['标识符'].isin(LEAKY_EVENTS)].copy()

# 保留原始target标签（从完整数据获取）
user_targets = df.groupby('user_id')['target'].max()
```

#### 防护效果
- 确保模型只学习"下单前"的行为特征
- 防止模型通过订单成功事件直接判断标签
- 保持预测场景与训练场景的一致性

#### 需弱化的特征列表
```python
PURCHASE_DIRECT_FEATURES = [
    'click_buy_now_cnt',      # 点击"立即购买"等按钮次数
    'step_sms_input',         # 输入验证码步骤
    'step_sms_submit',        # 提交验证码步骤
    'cnt_bussProcessing',     # 业务处理/办理次数
    'process_fail_count',     # 办理失败次数
    'max_intent_level',       # 最大意图等级
    'last_intent_level',      # 最后意图等级
]
```

#### 弱化配置
```python
FEATURE_WEAKENING_CONFIG = {
    'enabled': True,                    # 是否启用弱化
    'method': 'log_transform',          # 弱化方法
    'log_base': 2,                      # 对数底数
    'cap_percentile': 90,               # 百分位截断值
    'weight_decay_factor': 0.5,         # 权重衰减因子
}
```

#### 支持的弱化方法
| 方法 | 说明 | 公式 |
|------|------|------|
| `log_transform` | 对数变换 | `log1p(x) / log(base)` |
| `sqrt_transform` | 平方根变换 | `sqrt(abs(x)) * sign(x)` |
| `cap_percentile` | 百分位截断 | `clip(x, upper=percentile_value)` |
| `min_max_compress` | 归一化压缩 | `(x - min) / (max - min)` |

### 5.4 类别特征处理

#### 类别特征列表
```python
CAT_FEATURES = [
    'last_login_type',     # 最后登录方式
    'last_platform',       # 最后使用平台
    'preferred_brand',     # 偏好品牌
    'last_3_actions_seq'   # 最近3次行为序列
]
```

#### 处理方式
```python
# 1. 填充缺失值
for col in CAT_FEATURES:
    df[col] = df[col].fillna('unknown').astype(str)

# 2. 转换为LightGBM原生category类型
for col in CAT_FEATURES:
    X[col] = X[col].astype(str).astype('category')
```

## 附录A: 项目风险评估

### A.1 高风险项 (P1)

| 风险项 | 风险描述 | 影响 | 缓解措施 |
|--------|----------|------|----------|
| **特征弱化效果不稳定** | log_transform方法在不同数据分布下效果差异大 | 模型泛化能力波动 | 多方法对比测试，定期评估 |
| **特征泄露防护硬编码** | LEAKY_EVENTS列表需手动维护 | 新事件类型可能遗漏 | 建立事件类型审核流程 |
| **监控缺失** | 缺少生产环境监控告警 | 问题发现不及时 | 接入监控平台，配置告警 |

### A.2 中风险项 (P2)

| 风险项 | 风险描述 | 影响 | 缓解措施 |
|--------|----------|------|----------|
| **阈值失效** | 数据分布变化导致训练阈值不适用 | 预测准确率下降 | 定期回测，动态阈值 |
| **业务规则硬编码** | INTENT_RANK、BRANDS等规则写死 | 业务调整需改代码 | 配置外部化，热加载 |
| **API安全** | 仅API Key认证，无请求频率限制 | 暴力破解、DDoS风险 | 增加限流、IP白名单 |

### A.3 低风险项 (P3)

| 风险项 | 风险描述 | 影响 | 缓解措施 |
|--------|----------|------|----------|
| **ID解密容错** | Base64解码失败返回原值 | 部分用户ID不可读 | 增加解密成功率日志 |
| **时间格式单一** | 仅支持YYYYMMDDHHMMSS | 其他格式需预处理 | 扩展时间解析器 |
| **类别特征OOV** | 推理时出现训练未见类别 | LightGBM自动处理 | 监控未知类别比例 |

### A.4 风险监控指标

| 指标 | 阈值 | 告警级别 |
|------|------|----------|
| 模型AUC下降 | < 0.65 | P1 |
| 商机占比异常 | > 60% 或 < 10% | P1 |
| API错误率 | > 5% | P2 |
| 特征缺失率 | > 20% | P2 |
| 响应时间P95 | > 10s | P3 |
