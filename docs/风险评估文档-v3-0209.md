## 1. 模型策略风险

### 1.1 策略手段-购机相关特征弱化

**实现位置**: `config/feature_list.py`, `src/features/unified_fe.py:148-191`

**当前实现**:
```python
PURCHASE_DIRECT_FEATURES = [
    'click_buy_now_cnt',      # 点击"立即购买"次数
    'step_sms_input',         # 输入验证码步骤
    'step_sms_submit',        # 提交验证码步骤
    'cnt_bussProcessing',     # 业务处理次数
    'process_fail_count',     # 办理失败次数
    'max_intent_level',       # 最大意图等级
    'last_intent_level',      # 最后意图等级
]

FEATURE_WEAKENING_CONFIG = {
    'method': 'log_transform',  # 对数变换弱化
    'enabled': True,
}
```

**风险陈述**: 对购机强关联特征（验证码输入、点击购买等）进行对数变换弱化，可能导致模型对关键购买信号的捕捉能力下降，整体预测准确率降低；弱化程度难以精确量化，不同业务场景下效果不稳定，且当业务流程变化（如取消验证码环节）时，弱化策略可能产生反向效果。

**影响范围**:
- 模型 Precision/Recall 平衡点偏移
- 高意向用户识别率可能下降
- 不同月份/渠道效果波动加大

**缓解措施**:
- 建立 A/B 测试机制，持续对比弱化前后效果
- 监控弱化特征的重要性占比变化
- 设置弱化策略开关，支持快速回滚

---

### 1.2 策略手段-阈值自动优化与兜底逻辑

**实现位置**: `src/models/model_lgb.py:59-93`

**当前实现**:
```python
def optimize_by_metric(self, y_true, probs):
    # 业务硬约束：商机占比不能超过 50%
    if metrics['positive_rate'] > 0.5:
        continue

    # 兜底逻辑
    if not results:
        fallback_val = probs.mean() + probs.std()
        best_threshold = min(0.95, max(0.5, fallback_val))
```

**风险陈述**: 阈值基于训练数据分布自动优化，当线上数据分布发生漂移时（如促销期间用户行为模式变化），优化阈值可能失效；兜底逻辑采用统计值计算，在极端数据分布下可能产生不合理阈值；50%商机占比硬约束可能在某些业务场景下过于严格或宽松。

**影响范围**:
- 促销/节假日期间预测效果衰减
- 兜底阈值可能掩盖模型问题
- 业务约束与实际需求不匹配

**缓解措施**:
- 建立阈值监控告警，触发率异常时通知
- 定期（月度）重新评估阈值有效性
- 业务约束参数化配置，支持动态调整

### 1.3 策略手段-规则硬编码与意图等级映射

**实现位置**: `config/business_rules.py`, `src/features/unified_fe.py:22-31`

**当前实现**:
```python
# 意图等级硬编码
INTENT_RANK = {
    'zdscH5_PageView': 1, 'eventClick': 2, 'zdscLogin': 3,
    'bussinessProcessing': 4, 'orderSuccess': 5
}

# 特征泄露事件过滤（硬编码）
LEAKY_EVENTS = ['orderSuccess', 'server_orderSuccess', '支付成功', '办理成功']

# 关键词匹配规则
ACTION_KEYWORDS = {
    'buy': '立即购买|立即申请|去结算|立即下单|提交订单',
    'fail': '失败|错误|异常|未通过|校验失败',
}
```

**风险陈述**: 意图等级和关键词匹配规则硬编码在代码中，当业务埋点名称变更、新增行为类型或文案调整时，规则无法自动适配，需要修改代码并重新部署；多处规则分散在不同文件，缺乏统一管理，可能产生规则冲突或遗漏。

**影响范围**:
- 埋点变更导致特征失效
- 新业务场景无法自动覆盖
- 规则维护成本持续上升

**缓解措施**:
- 规则配置化，从代码中分离到配置文件
- 建立埋点变更通知机制
- 定期审计规则有效性

## 2. 特征工程风险

### 2.1 特征泄露防护依赖硬编码

**实现位置**: `src/features/unified_fe.py:20-28`

**风险描述**: 特征泄露防护通过硬编码 `LEAKY_EVENTS` 列表实现，如果新增结果型事件未及时加入列表，将导致模型在训练时使用了未来信息，线上预测效果显著低于离线评估。

**当前防护范围**:
- `orderSuccess`
- `server_orderSuccess`
- `支付成功`
- `办理成功`

**风险等级**: 高

**缓解措施**:
- 建立埋点事件类型元数据管理
- 训练前自动检测潜在泄露特征
- 对比离线/线上指标差异，异常时告警

---

### 2.2 类别特征基数膨胀

**实现位置**: `src/features/unified_fe.py:105`

**风险描述**: `last_3_actions_seq` 特征将最近3次行为拼接为字符串序列，可能产生数千种组合，导致类别特征基数过大，模型过拟合且推理效率下降。

```python
fe['last_3_actions_seq'] = grouped['标识符'].apply(
    lambda x: "_".join(x.tail(3).astype(str).tolist())
)
```

**风险等级**: 中

**缓解措施**:
- 对低频组合进行归并（如出现次数<100归为"Other"）
- 考虑使用 Embedding 或 Target Encoding 替代

---

### 2.3 品牌识别逻辑脆弱

**实现位置**: `src/features/unified_fe.py:98-102`, `config/business_rules.py:7`

**风险描述**: 品牌识别采用硬编码关键词匹配，顺序优先匹配第一个命中品牌，无法处理多品牌商品或新品牌。

```python
BRANDS = ['Apple', '苹果', '华为', 'HUAWEI', '荣耀', '小米', 'OPPO', 'VIVO', '小天才']

def get_top_brand(names):
    name_str = " ".join(names.astype(str))
    for b in BRANDS:
        if b in name_str: return b
    return 'Other'
```

**风险等级**: 低

**缓解措施**:
- 定期更新品牌列表
- 考虑使用品牌词库或 NER 模型

## 3. 数据处理风险

### 3.1 用户ID解密容错不足

**实现位置**: `src/data/loader.py:18-27`

**风险描述**: Base64 解密失败时静默返回原始字符串，可能导致同一用户产生多个不同 ID，影响用户行为聚合的准确性。

```python
def decode_phone(text):
    try:
        return base64.b64decode(text_str).decode('utf-8')
    except:
        return text_str  # 静默降级，无日志记录
```

**风险等级**: 中

**缓解措施**:
- 增加解密失败日志和监控
- 统计解密失败率，异常时告警

---

### 3.2 时间格式解析单一

**实现位置**: `src/data/loader.py:56-66`, `api/predict.py:142-158`

**风险描述**: 仅支持 `YYYYMMDDHHMMSS` 格式，其他时间格式（ISO 8601、时间戳等）将被丢弃。

**风险等级**: 中

**缓解措施**:
- 支持多种时间格式自动识别
- API 文档明确时间格式要求

---

### 3.3 数据文件分隔符探测

**实现位置**: `src/data/loader.py:32-42`

**风险描述**: 通过尝试多种分隔符加载文件，依赖列数判断是否成功，可能在特殊数据情况下误判。

**风险等级**: 低

## 4. API服务风险

### 4.1 API密钥管理

**实现位置**: `api/auth.py`, `api/config.py`

**风险描述**:
- 密钥通过环境变量或 `.env` 文件管理，存在泄露风险
- 仅支持单一密钥，无密钥轮换机制
- 无请求频率限制，存在暴力破解风险

**风险等级**: 中

**缓解措施**:
- 生产环境使用密钥管理服务（如 Vault）
- 实现密钥轮换机制
- 增加请求频率限制（Rate Limiting）

---

### 4.2 模型热加载缺失

**实现位置**: `api/predict.py:49-81`

**风险描述**: 模型仅在服务启动时加载一次，更新模型需要重启服务，存在服务中断风险。

**风险等级**: 中

**缓解措施**:
- 实现模型版本管理和热更新机制
- 使用蓝绿部署或滚动更新

---

### 4.3 批量请求资源控制

**实现位置**: `api/main.py:212-220`, `api/config.py:57`

**当前限制**:
```python
MAX_BATCH_SIZE: int = 10000  # 单次最大记录数
```

**风险描述**: 大批量请求可能导致内存溢出或响应超时，影响服务稳定性。

**风险等级**: 中

**缓解措施**:
- 根据服务器资源动态调整限制
- 实现请求队列和异步处理

---

## 5. 部署运维风险

### 5.1 Docker镜像体积

**实现位置**: `Dockerfile`

**风险描述**: 镜像包含完整 Miniconda 环境，体积较大（预估 2-4GB），影响部署效率和存储成本。

**风险等级**: 低

**缓解措施**:
- 使用多阶段构建优化镜像体积
- 考虑使用更精简的基础镜像

---

### 5.2 日志与监控缺失

**风险描述**:
- 缺少结构化日志输出
- 无预测结果分布监控
- 无模型性能衰减告警

**风险等级**: 高

**缓解措施**:
- 接入统一日志平台（ELK/Loki）
- 建立预测分布监控看板
- 设置 AUC/准确率衰减告警

---

### 5.3 数据备份与恢复

**风险描述**: 模型文件和配置无自动备份机制，文件损坏或误删后无法快速恢复。

**风险等级**: 中

**缓解措施**:
- 模型文件版本化存储（如 S3/OSS）
- 建立定期备份机制
