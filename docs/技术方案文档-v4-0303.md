## 三、效果瓶颈分析（按影响力排序）

### 瓶颈 1：验证方式失真 — 随机切分导致指标虚高 🔴

**现象**：训练 AUC 0.993，回测 Precision 60-71%，差距 >0.25。

**根因**：`train_test_split(random_state=42)` 把 8-9 月数据随机混洗。同一促销周期、同一时间窗口的用户同时出现在训练集和测试集，模型记住了时间段特征而非用户意图。

**影响**：在这个虚假基线上做的所有特征优化和调参，效果都不可信。

**位置**：`train_pipline.py` 第 74-76 行

```python
# 当前（有问题）
train_df, test_df = train_test_split(
    feature_df, test_size=0.2, random_state=42, stratify=feature_df['target']
)
```

### 瓶颈 2：样本不平衡处理不足 🔴

**现象**：正样本率 ~1%（4,012 / 412,311），`scale_pos_weight` 搜索范围仅 1.0~5.0。

**根因**：理论最优 `scale_pos_weight ≈ 负样本数/正样本数 ≈ 100`。当前范围太窄，Optuna 根本搜不到合理值。加上 `n_trials=8`，10+ 维超参空间里 8 次尝试约等于随机猜。

**影响**：模型对正样本的学习严重不足，Recall 虚高但 Precision 低。

**位置**：`src/models/model_lgb.py` 第 122 行、第 95 行

```python
# 当前（有问题）
'scale_pos_weight': trial.suggest_float('scale_pos_weight', 1.0, 5.0)
# n_trials=8  太少
```

### 瓶颈 3：阈值在过拟合训练集上搜索 🟡

**现象**：阈值锁定在 0.300，回测时 Precision 偏低。

**根因**：训练集过拟合 → 概率分布两极化（大量 0.99+ 和 0.01-）→ 搜出的 0.300 阈值在更平滑的回测概率分布上不适用。

**影响**：阈值不可迁移，回测时要么漏掉真正高意向用户，要么混入大量噪声。

**位置**：`src/models/model_lgb.py` 第 206-207 行

```python
# 当前（有问题：在训练集上搜阈值）
train_probs = self.model.predict(X_train)
self.optimize_by_metric(y_train, train_probs)
```

### 瓶颈 4：单特征垄断（view_detail_cnt 独占 59.40%）🟡

**现象**：剔除购买流程特征后，`view_detail_cnt` 成为新的垄断特征。

**根因**：正样本用户的累计浏览次数天然远高于负样本，模型只需一个简单阈值就能区分大多数样本，退化为单特征规则。

**影响**：模型丧失多维信号学习能力，泛化到新数据时一旦该特征分布偏移就崩盘。

### 瓶颈 5：缺少"意图前兆"特征 🟡

**现象**：当前 30 个特征几乎都是单次会话的聚合统计，缺少反映用户犹豫/决策过程的行为模式。

**缺失维度**：

| 缺失特征 | 业务含义 |
|----------|---------|
| 跨天回访次数 | 多天反复来看 = 在认真考虑 |
| 浏览商品多样性 | 看了很多不同手机 = 在比价 |
| 会话数 | 多次打开 App = 持续关注 |
| 意图加速度 | 行为等级逐步升高 = 接近决策 |

### 瓶颈 6：特征冗余浪费模型容量 🟢

| 特征 A | 特征 B | 关系 |
|--------|--------|------|
| `conversion_efficiency` | `click_to_process_rate` | 公式完全一致 |
| `max_intent_level` | `last_intent_level` | 强相关 |
| `recent_3_avg_intent` | `recent_5_avg_intent` | `intent_trend` 已是其差值 |

## 四、实验计划

### 原则

- 先修验证体系（瓶颈 1-3），得到可信基线
- 再叠加特征优化（瓶颈 4-6），在可信基线上观察真实提升
- 每次只改一个变量，对照观察

### 实验清单

| 序号 | 实验 | 解决瓶颈 | 改什么 | 优先级 |
|:---:|------|:-------:|-------|:-----:|
| **E1** | 时间切分验证 | #1 | `train_pipline.py`：8月训练 / 9月验证 / 10月回测 | **P0** |
| **E2** | 超参搜索修正 | #2 | `model_lgb.py`：`scale_pos_weight` 1~100，`n_trials` 30 | **P0** |
| **E3** | 阈值改验证集搜索 | #3 | `model_lgb.py`：用验证集而非训练集搜阈值 | **P0** |
| **E4** | view_detail_cnt 压缩 | #4 | `unified_fe.py`：log1p 压缩 + 新增 `detail_view_ratio` | **P1** |
| **E5** | 新增意图前兆特征 | #5 | `unified_fe.py`：`active_days` / `unique_items_viewed` / `session_count` / `intent_acceleration` | **P1** |
| **E6** | 删除冗余特征 | #6 | `unified_fe.py`：删 `conversion_efficiency`、合并 intent gap | **P1** |
| **E7** | 正样本质量筛选 | 噪声 | `train_pipline.py`：`total_actions < 3` 的正样本降权至 0.3 | **P2** |

> E1-E3 可以一起做（同属验证体系修正），E4-E6 可以一起做（同属特征优化）。

### E4：view_detail_cnt 压缩

```python
# unified_fe.py — 在 view_detail_cnt 计算之后追加
fe['detail_view_ratio'] = fe['view_detail_cnt'] / (fe['total_actions'] + 1)
fe['view_detail_cnt'] = np.log1p(fe['view_detail_cnt'])
```

### E5：新增意图前兆特征

```python
# unified_fe.py — 新增维度
fe['active_days'] = grouped['trigger_time'].apply(lambda x: x.dt.date.nunique())
fe['is_multi_day_visitor'] = (fe['active_days'] >= 2).astype(int)
fe['visit_span_days'] = grouped['trigger_time'].apply(
    lambda x: (x.max() - x.min()).total_seconds() / 86400.0
)
fe['unique_items_viewed'] = grouped['商品名称'].nunique()
fe['repeat_view_ratio'] = fe['view_detail_cnt'] / (fe['unique_items_viewed'] + 1)

SESSION_GAP = 1800
fe['session_count'] = grouped['diff_time'].apply(lambda x: (x > SESSION_GAP).sum() + 1)
fe['actions_per_session'] = fe['total_actions'] / (fe['session_count'] + 0.1)

fe['intent_acceleration'] = grouped['intent_level'].apply(
    lambda x: (x.diff().tail(3) > 0).sum() if len(x) >= 3 else 0
)
```

### E6：删除冗余特征

```python
# unified_fe.py — 删除 conversion_efficiency（与 click_to_process_rate 完全一致）
# 删除这行：fe['conversion_efficiency'] = fe['cnt_bussProcessing'] / (fe['cnt_eventClick'] + 1)
```

```
         ↓ 产出可信基线                    ↓ 产出特征优化增量            ↓ 最终微调
```
